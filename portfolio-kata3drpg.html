이동, 기본 공격, 스킬 입력이 겹치는 문제

문제

이동 중 공격하거나 기본 공격 중 스킬을 사용하면
이전 행동이 끝나기 전에 새로운 입력이 들어와
이동과 공격 애니메이션이 겹치는 문제가 있었습니다.

원인

이동과 공격 입력은 계속 확인되지만,
실제 공격은 애니메이션이 진행되는 동안 처리됩니다.

현재 공격이 끝났는지 확인하지 않고 새로운 입력을 받으면
기존 행동이 중간에 끊기거나
다른 애니메이션으로 덮어써질 수 있었습니다.

해결

_castingSkill과 _currentSkillHash를 사용해
현재 스킬 사용 상태를 확인하고,

스킬이 진행 중일 때는
이동과 기본 공격 입력을 제한했습니다.

공격 판정은 OnSkillHitEvent,
스킬 종료는 OnSkillEndEvent에서 처리해
입력 시점과 실제 공격 시점을 분리했습니다.

결과

공격이나 스킬이 진행되는 동안
다른 입력이 끼어드는 문제를 막았고,

애니메이션 타이밍에 맞춰 공격 판정과 데미지가
정상적으로 적용되도록 정리했습니다.

몬스터가 죽은 뒤 다시 생성될 때 수량이 꼬이는 문제

문제

몬스터가 죽은 뒤 다시 생성될 때,
아직 생성 중인 몬스터를 확인하지 못해
같은 몬스터를 여러 번 생성 요청하는 문제가 있었습니다.

원인

몬스터는 생성 요청 후 바로 나타나는 것이 아니라
코루틴을 통해 일정 시간이 지난 뒤 생성됩니다.

이 때문에 실제 몬스터 수만 확인하면
이미 생성이 예약된 몬스터를
다시 부족한 수로 판단할 수 있었습니다.

해결

_monsterCount로 현재 존재하는 몬스터 수를 관리하고,
_reserveCount로 생성 대기 중인 몬스터 수를
따로 관리했습니다.

두 값을 합쳐 목표 몬스터 수와 비교하고,
실제로 부족한 경우에만 ReserveSpawn을 실행하도록 수정했습니다.

결과

생성 예정인 몬스터까지 수량에 포함하면서
중복 생성 요청을 막았고,

항상 설정한 목표 수에 맞게
몬스터가 유지되도록 했습니다.

HP / EXP / Level UI 갱신이 누락될 수 있는 문제

문제

전투 중 HP 감소, 경험치 획득, 레벨업처럼
여러 상황에서 스탯이 변경되기 때문에

HUD가 항상 최신 값을 표시하도록
관리할 필요가 있었습니다.

원인

스탯이 변경되는 위치마다 HUD를 직접 갱신하면
새로운 기능이 추가될 때 UI 갱신 코드를 빠뜨리거나

같은 갱신을 여러 곳에서
호출할 수 있었습니다.

해결

Stat.OnChanged 이벤트를 통해
스탯이 변경되었음을 알리고,

UI_HUD가 해당 이벤트를 구독하도록 구성했습니다.

실제 HP, EXP, Level 표시는
RefreshHUD에서 한 번에 갱신하도록 통합했습니다.

결과

스탯을 변경하는 로직과
화면에 표시하는 로직을 분리했고,

전투와 경험치 획득, 레벨업 이후의 HUD 갱신을
하나의 흐름으로 관리할 수 있게 되었습니다.

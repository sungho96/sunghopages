Finite State Machine(유한 상태 기계)

최종 수정일: 2월 24일

정의

FSM는 시스템이 가질 수 있는 상태가 유한 개로 정혀져있고, 어떤 시점에도 시스템은 그중 정확히 하나의 상태에 있으며, 입력/조건에 의해 정해진 규칙대로 상태가 전이(Transition)되는 모델입니다.

핵심 규칙

state는 유한 개

상태목록이 명확히 정의되어야합니다.

현재 상태는 1개

동시에 Idle이면서 Attack 같은 모호함을 허용하지 않는 것이 기본 모델입니다.

전이는 규칙으로만 발생

상태변경은 조건/입력에 의해 일어나면,임의로 섞이지 않도록 제한합니다.

구성 요소(용어 정리)

state(상태): 시스템의 동작모드

Evnet/Input(입력): 외부에서 들어오는 트리거(버튼, 충돌, 시간 만료 등)

Condtion/Guard(가드 조건) : 전이가 허용되는 조건식

Transition(전이): (현재 상태, 입력/조건) -> 다음 상태 규칙

Action(동작): 상태에 속한 실행 로직

실무에서 State마다 "들어갈 때(Enter)/머무는동안(Update)/나갈때(Exit)로 동작을 분리해서 문서화하는 경우가 많습니다.

표현 방식

상태전이 표

행: 현재 상태

열: 입력 조건

값 : 다음상태

상태 전이 다이어그램

노드: 상태

화살표: 전이(조건/입력 라벨 포함)

상태 명세서

Enrty 조건 : 어떤 전이로 들어가는가

Exit 조건 : 어떤 전이로 나가는가

In-state Action: 상태 유지 중 수행되는 행동

Forbidden: 이 상태에서 하면 안 되는 행동(금지 규척)

FSM 사용 목적

행동 상호 배타성 보장

공경 중에는 이동 로직이 돌면 안된다.

죽은 상태에서는 입력이 먹으면 안된다.

상태전환 조건을 한곳에 모으기

if문이 여러 스크립트에 흩어지면 디버깅이 어려움

주의 사항

FSM if문 제거가 목적이 아닙니다.

if문을 '전이 규칙'으로 격리 하는 것이 목적입니다.

상태가 너무 많아지면 FSM도 복잡해집니다.

이 경우 상위/하위 상태(계층형 FSM)나 서브 FSM로 분리합니다.

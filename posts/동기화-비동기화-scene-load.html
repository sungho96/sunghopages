동기화 / 비동기화 (Scene Load)

정의

Unity에서 동기화 방식은 작업이 순서대로 즉시 실행되며, 현재 작업이 끝나야 다음 작업으로 진행되는 처리 방식임.

반면 비동기화 방식은 메인 흐름을 가능한 한 유지하면서, 시간이 걸리는 작업 또는 지연이 필요한 작업을 분리하여 처리하는 방식임.

씬 로드 활용 관점에서는, 사용자 입력 직후 즉시 씬을 전환하는 방식과 메시지 표시, 페이드 연출, 로딩 대기 등의 과정을 거친 뒤 씬을 전환하는 방식을 구분해서 이해 할 수 있음.

핵심 규칙

동기화는 순차 실행이 핵심

현재 로직이 끝나기 전까지 다음 단계로 넘어가지 않는 흐름

비동기화는 메인 흐름 유지 + 시점 분리가 핵심

입력 처리, UI 반응, 연출 등을 유지하면서 나중에 작업을 이어서 실행함.

씬로드 전 UX 단계가 있으면 비동기 흐름 제어가 유리

성공 메시지 표시, 페이드, 로딩 안내, 사운드 재생 완료 대기 등에 적합함.

코루틴은 멀티스레드가 아니라 메인 스레드 기반 흐름 제어

유니티에서 자주 쓰이는 비동기적 표현 방식이지만, 일반적인 스레드 병렬 처리와 동일 개념은 아님.

씬 로드 방식은 연출 목적과 로딩 비용에 맞게 선택

간단한 전환은 즉시 로드

연출/로딩 UI 필요하면 지연 실행 또는 비동기 로드 방식을 고려함.

구성 요소

동기화(Synchronous) : 작업이 순서대로 즉시 실행되며, 앞선 작업 완료가 다음 작업의 진행 조건이 되는 방식

비동기화(Asynchronous): 작업 완료시점을 분리하여 메인 흐름을 유지하면서 이후 처리(콜백/코루틴/비동기 로드 등)을 수행하는 방식

코루틴(Coroutine): yeild 기반으로 실행을 잠시 멈췄다가 다시이어가는 Unity의 흐름 제어 방식.

WaitForSeconds: 코루틴 내에 지정 시간만큼 대기 후 다음 로직으로 진행하도록 만드는 지연 도구.

Scene Load: 현재 씬에 다른 씬으로 전환하는 처리, 게임 진행 단계 전환, UI 흐름 분리 등에 사용됨.

로딩 연출(Loading UX): 씬 전환 중 사용자에게 진행 샅애/안내 메시지/페이드 등을 제공하는 사용자가 경험 처리

유사함수

StartCoroutine: 코루틴 실행을 시작하여 지연 실행 또는 단계적 흐름 제어를 가능하게 함.

WaitForSeconds: 코루틴 내부에서 일정 시간 대기후 다음 처리로 넘어가게 함.

SceneManager.LoadScene: 대상 씬을 로드하여 화면/상태를 전환 함.

SceneManager.LoadSceneAsync: 씬을 비동기적으로 로드하여 로딩 UI와 함께 사용 하기 좋은 방식임.

AsyncOperation: 비동기 씬 로드 진행 상태를 확인하거나 완료 시점을 제어할 때 사용 하는 Unity 객체 임.

주의사항

코루틴 = 완벽한 병렬 처리로 오해하면 안됨.

코루틴은 메인 스레드 기반 흐름 제어이므로, 무거운 연산 자체를 해결하는 도구는 아님.

지연후 씬 로드전, 객체 생명주기 고려 필요

대기 중에 UI/오브젝트가 비활성화되거나 파괴되면 이후 로직이 기대대로 동작하지 않을 수 있음.

씬 전환 직전 UI 반영 타이밍 확인

메시지를 보여주고 바로 씬을 바꾸면 사용자가 보지 못할 수 있으므로, 지연 시간/연출 길이를 조정해야함.

중복 입력으로 코루틴이 여러 번 실행되지 않게 제어 필요

버튼 연타 시 씬 로드 요청이 중복되면 예기치 않은 전환 문제가 생길 수 있음.

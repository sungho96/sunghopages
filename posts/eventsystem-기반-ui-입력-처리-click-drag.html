EventSystem 기반 UI 입력 처리(Click/Drag/Hover)

최종 수정일: 2월 20일

정의

EventSystem 기반 UI 입력 처리는 Unity UI 입력처리는Unity UI(UGUI)에서 마우스/터치 입력을 클릭(click),드래그 같은 이벤트로 변환해 UI 오브젝트에 전달하는 방식임. UI 입력은 물리 충돌(physics)이 아니라 UI Raycast(Graphic Raycast)를 통해 처리됨

핵심 규칙

UI 입력 이벤트는 EventSystem 이 존재할 때만 정상 동작함.

canvas는 입력을 받기 위해 Graphic Raycaster가 필요함.

(보통 canvas생성시 자동으로 컴포넌트 됨)

입력 대상 UI는 보통 Raycast Target이 활성화되어야 포인터가 감지됨.

클릭/드래그/호버 처리는 인터페이스 기반 콜백(클릭/드래그 핸들러)로 받는 방식이 표준임

호버(Enter/Exit)는 "포인터가 올라갔다/벗어났다"를 의미하며, 클릭이 없어도 발생 할 수 있음.

드래그는 "누른 상태에서 이동"을 전제로 하며, 이벤트는 데이터 주로 스크린 좌표를 제공함.

UI가 겹칠 경우레이캐스트 결과 우선순위(정렬/레이어/그래픽) 설정에 따라 이벤트가 전달됨.

구성요소(용어 정리)

EventSystem : UI 입력 이벤트를 생성,전달하는 핵심 시스템 오브젝트

Input Moudule : 마우스/터치/기타 입력을 EventSystem 이벤트로 변환하는 모듈

(예Standalone/Touch 계열)

Graphic Raycaster: Canvas에서 UI요소를 대상으로 레이캐스트를 수행하는 컴포넌트

Raycast Target: 해당 UI 그래픽이 레이캐스트에 "잡히는지를" 결정하는 옵션

IPointerClickHandler: 클릭 이벤트를 콜백을 받는 인터페이스

IDragHandler: 드래그 이벤트를 콜백 받는 인터페이스

IPointerEnterHandler : 포인터가 UI 위로 진입 할때(호버 시작) 콜백을 받는 인터페이스

IPointerExitHandler : 포인터 입력 정보(위치, 버튼, 드래그 상태 등)를 담는 이벤트 데이터

PointerEventData : 포인터 입력 정보(위치, 드래그 상태)를 담는 이벤트 데이터

Canvas Render mode:

Screen Space/World Space등 UI 좌표,입력 처리에 영향을 주는 캔버스 모드

주의사항

EvnetSystem이 없거나 Input Module이 비활성/누락되면 클릭/드래그가 발생하지 않음.

Raycast Target이 꺼져 있거나, 투명/마스크/레이어 설정으로 레이캐스트가 막히면 입력이 안들어올 수 있음.

호버(Enter/Exit)는 포인터가 실제로 레이캐스트 "잡히는 그래픽" 위를 지나야 안정적으로 발생함.(이미지/텍스트가 없는 빈 영역, 레이캐스트 대상이 없는 오브젝트는 기대한 대로 안잡힐 수 있음)

드래그에서 제공되는 포인터 위치는 보통 화면 좌표이므로, UI이동/배치 시 캔버스 모드에 따라 좌표 변환이 필요할 수 있음.

UI가 서로 겹쳐 있으면 의도한 오브젝트가 아닌 상위(앞쪽)UI가 이벤트를 가져갈 수 있음.

Worlid Space Canvas나 카메라 설정에 따라 레이캐스트 기준이 달라져 입력이 예상과 다르게 동작 할 수 있습니다.

Enter/Exit는 클릭이 아니라 포인터 이동 기반이라 모바일 환경에서는 기대 빈도/방식이 달라 질 수 있습니다.

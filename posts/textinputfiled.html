TextInputfiled

최종 수정일: 2월 19일

정의

TextUnputfiled는 사용자가 키보드/모바일 키패드로 문자열을 입력할 수 있게 하는 UI 입력 컴포넌트(일반적으로 InputField 또는 TextMeshpro의 TMP_InputField를 의미)

입력 값은 텍스트로 저장되면, 포커스/선택영역/플레이스홀더 등이 동작함.

핵심 규칙

입력 UI는 포커스를 가져야 타이핑이 들어감.(선택/활성화 상태 관리가 중요)

입력 타입(일반/비밀번호/숫자 등)은 Content Type 같은 설정으로 제한함.

값 읽기는 보통 현재 문자열(text) 기준이며, 입력 완료/값 변경 시점을 구분함.(변경 중 vs 제출/완료) 사용자 경험을 위해 초기 포커스, 엔터 키 제출,탭 이동,실패시 포커스 복귀 같은 흐름을 미리 설계함.

모바일에서는 키보드가 뜨는 타이밍/종류가 중요하므로 입력 제한과 키보드 타입을 함께 고려함.

구성요소(용어 정리)

TextArea:사용자가 실제로 입력/표시되는 텍스트 영역

PlaceHolder: 비어있을때 안내문구

Caret(커서): 현재 입력 위치를 표시하는 깜빡이는막대

Selection(선택영역): 드래그/Shift로 선택된 범위 표시

Content Type: 입력 형식 제한(pw, integer, Decimal 등)

Character Validation: 허용 문자 규칙(숫자만, 이메일 형식 등)

Line Type: 한 줄/여러 줄 입력

Submit/End edit: 입력완료(엔터/포커스 해제 등)시점 이벤트 개념

Focus/Activate: 입력을 받아 준비가 된 활성 상태(키 입력이 들어오는 상태)

유사함수

Select() : 해당 입력칸을 선택 상태로 만들어 포커스 준비를 함.

.

ActivateInputField() : 실제로 키 입력을 받도록 입력 상태를 활성화 함.

DeactivateInputField(): 입력 상태를 종료하고 포커스를 해제 함.

ForceLabelUpdate(): 설정 변경 후 표시 텍스트를즉시 갱신 함.

MoveTextEnd(bool Shift): 커서를 텍스트 끝으로 이동(shif로 선택 확장 가능)함.

주의 사항

오탑/타입 혼동: TextInputfiled처럼 이름이 섞이면 컴포넌트/타입 연결이 끊기기 쉬움

. InputField 철자를 먼저 확정.

비밀번호 마스킹은 설정만으로 끝나지 않을 수 있음: Content Type= Password로 바꾼 뒤 표시 갱신이 필요할 때가 있음.

포커스 제어를 안하면 UX가 급격히 나빠짐 : 실패 메시지 닫은 뒤 입력칸으로 다시 돌아오지 않으면 사용자가 매번클릭해야 함.

값 검증 타이밍: OnvalueChaged에서 검증하면 과하게 방해 될 수 있고, OnEndEdit/제출 시점에서 검증하면 자연 스러움.

EventSystem/입력 모듈 영향: 입력이 안들어오면(커서가 안뜸) 대부분 포커스/이벤트 쪽 문제일 확률이 높음.

Monster AI

정의

Monster AI는 몬스터가 플레이어를 탐지 → 추적 → 공격 → 재판단(재추적/연속공격/복귀) 하는 흐름을 상태 기반으로 처리하는 로직임.

Unity에서는 상태(State) + NavMeshAgent + 애니메이션 이벤트를 조합해 구현하며, 이동/공격 판단을 분리하면 동작이 안정적이고 디버깅이 쉬워짐.

핵심규칙

상태별 책임을 분리해야 함.

ex : idle =탐지, Moving= 추적, Skill= 공격 방향 유지

탐지 범위와 공격 범위 기준을 명확히 나눠야 함.

탐지 시작 거리와 실제 공격 시작 거리가 섞이면 AI가 흔들림.

추적대상(Lock Target) 유효성 검사를 매 프레임 해야 합니다.

타겟이 사라지거나 죽으면 즉시 상태를 정리해야함.

이동 목적지는 계속 갱신해야 함.

타겟이 움직이는 경우 초기 위치만 저장하면 추적이 끊김.

공격 판정은 애니메이션 타이밍과 동기화하는 것이 좋음

공격 시작 시점이 아니라 실제 타격 프레임에 판정하는 방식이 자연스러움.

도착 판정(임계값을)이 있어야함.

정확히 0 거리만 비교하면 미세 떨림/ 상태 반복 전환이 생길 수 있음.

회전은 수평 기준 처리 여부를 일관되게 정해야 함.

지형/높이 차가 있을 때 상하 회정까지 포함하면 어색 해질 수 있음.

구성요소

State(상태): 몬스터 현재 행동 단계

Scan Range(탐지 범위): 플레이어를 인식하고 추적하는 시작하는 거리

Attack Range(공격 범위): 공격 상태로 전환하는 거리

Lock Target: 현재 추적/공격 중인 대상 참조

Destnation: 이동 목표 위치(타겟 위치 또는 특정 지점)

Animation Event: 애니메이션 특정 프레이멩서 함수 호출(타격 판정용)

Stat: 체력/공격력/방어력/이동속도 등 전투 수치 데이터

Roatation Interpolation(회전 보간): 자연스러운 방향 전환 처리

Arrival Threshold(도착 임계값): 목적지 도달로 판단하는 최소 거리 기준

주의사항

NavMeshAgent 누락 시 이동 관련 오류가 발생할 수 있음.

타겟 null 처리 부족시 예외나 상태 꼬임이 생길 수 있음.

공격/추적/피격 이후 타겟 상태를 자주 점검 해야함.

상태 전환 조건 중복이 있으면 Idle↔Moving↔Skill 전환이 떨릴 수 있음

거리 기준과 전환 우선순위르 명확히 두는 것이 중요합니다.

애니메이션 이벤트 의존 로직은 이벤트 누락 시 데미지가 안 들어갈 수 있음.

애니메이션 클립 이벤트 등록 여부를 꼭 확인해야 함.

수직 방향 포함 회전은 지형에 따라 모슨터가 과하게 들썩여 보일 수있음.

근접 몬스터는 보통 수편 회전만 쓰는 편이 안정적임.

상속

정의

유니티에서 상속은 기존 클래스(부모 클래스)의 공통 기능과 데이터를 물려 받아, 새로운 클래스에서 재사용.확장.변경하는 객체지향 설계 방식임.

유니티에서는 보통 MonoBehaviour를 기반으로 공통 클래스(컨트롤러/UI_Base/매니저 베이스)를 부모로 두고, 자식 클래스가 기능을 구체화하는 방식으로 많이 사용 됨

핵심 규칙

공통 기능은 부모 클래스에 배치

여러 클래스에서 반복되는 상태값, 참조, 캐싱, 공통 메서드 등은 부모 크래스에 모아 재사용성을 높임.

자식 클래스는 "확장/구체화"에 집중

자식 클래스는 부모 기능을 그대로 쓰거나, 필요한 부분만 재정의 역할을 분리함.

접근 제한자는 설계가 중요

자식에서 사용해야하는 필드/메서드는 protected, 외부에서 직접 건드리지 안되는 값은 private등으로 의도를 분명히 해야 함.

재정의가 필요한 메서드는 부모에서 확장 가능하게 선언

부모에서 확장 지점을 열어두고, 자식에게 목적에 맞게 동작을 바꾸는 구조가 상속의 핵심.

상속은 "관계과 명확할 때만" 사용

단순 기능 묶음이나 조합이 더 적합한 경우에는 상속보다 컴포넌트를 분리를 우선 고려 해야함.

구성 요소

부모 클래스(Base Class/Parent Class): 공통 데이터와 공통 동작을제공하는 기준 클래스

자식클래스(Derived Class/Child Class): 부모 클래스를 상속받아 기능을 확장하거나 구체화한 클래스

상속(Inheritance): 부모 클래스의 멤버(필드/메서/프로퍼터)를 자식 클래스가 물려받는 구조

접근 제한자(Access Modifier): public, protected, private 등 멤버의 접근 가능 범위를 제어 하는 규칙

기반 클래스 참조(Base Type Reference): 부모 타입으로 자식 객체를 다루는 방식으로, 공통 처리와 구조 단순화에 유리함

유사함수

GetComponent<T>() : 같은 오브젝트에서 부모 타입 또는 파생 타입 컴포넌트를 찾아 공통 처리에 활용할 때 사용됨.

TryGetComponent<T>(Out T): 상속 계열 컴포넌트 참조를 Null 예외 없이 안전하게 확인할때 유용 함.

GetComponentInParent<T>(): 상위 오브젝트 계층에서 공통 베이스 타입 컴포넌트를 찾아 연결할 때 사용됨.

GetCompoentInChildren<T>(): 하위 오브젝트 계층에서 공통 타입/파생 타입 컴포넌트를 탐색할 때 사용됨.

base.메서드명(): 자식 클래스에서 부모의 공통 로직을 유지하면서 확장 동작을 추가 할 때 사용하는 호출 방식.

주의사항

상속이 깊어질수록 추적이 어려워질 수 있음.

부모→자식→손자 구조가 길어지면 어디서 값이 바뀌는지 파악이 어려워짐.

부모 클래스 책임이 과도해지지 않도록 주의

모든 공통 기능을 무리하게 넣으면 부모 클래스가 비대해지고 수정 영향 범위가 커짐.

접근 제한자를 느슨하게 두면 구조가 무너짐

자식 편의를 위해 무분별하게 public을 늘리면 캡슐화가 깨지고 유지보수가 어려워짐.

유니티 생명주기 함수 사용시 의도 불명확 문제

부모와 자식이 각각 생명주기 함수를 가질 때 초기화 순서/중복 실행 의도를 명확히 해야함.

상속과 컴포넌트 조합을 혼동하지 않기

유니티는 컴포넌트 기반 구조가 핵심이므로, 모든 확장을 상속으로 해결하려 하면 오히려 복잡 해짐.

보스 네트워크 인스턴스 불일치

문제

보스전에서 Host와 Client 화면의 보스 위치와 행동 타이밍이 서로 다르게 보였습니다.

Host에서는 보스가 이미 이동하거나 스킬을 사용하고 있었지만,
Client에서는 다른 위치에 있거나 스킬 이펙트와 공격 타이밍이 늦게 보이는 문제가 발생했습니다.
처음에는 단순 네트워크 지연 문제로 의심했습니다.

원인

디버그 로그로 보스의 NetworkObject 상태를 확인한 결과,
Host와 Client가 같은 보스 인스턴스를 공유하지 않고
각자 다른 보스 오브젝트를 기준으로 동작하고 있는 것을 확인했습니다.

기존 보스 오브젝트가 네트워크 Spawn 대상으로 제대로 관리되지 않아,
Host와 Client에서 보스 AI, 위치, 스킬 실행이 서로 다른 기준으로 처리되고 있었습니다.

해결

실제 사용해야 하는 보스 프리팹을 NetworkObject 기반으로 정리하고,
보스가 씬에서 하나의 네트워크 인스턴스로 Spawn되도록 수정했습니다.

Client에서는 보스 AI를 직접 실행하지 않도록 막고,
Server가 보스 이동, 스킬 실행, 공격 판정을 담당하도록 구조를 정리했습니다.
이후 Client는 Server에서 전달받은 보스 위치와 상태를 기준으로 표시되도록 개선했습니다.

결과

Host와 Client가 서로 다른 보스를 기준으로 전투하던 문제가 해결되었고,
양쪽 화면에서 동일한 보스 위치와 행동을 기준으로 전투가 진행되도록 개선했습니다.

스킬 애니메이션 상태 충돌

문제

DownStrike와 ShieldBlock 스킬 사용 중 애니메이션이 끝까지 재생되지 않고, 중간에 Idle 또는 Run 상태로 전환되는 문제가 발생했습니다.

원인

이동 컨트롤러가 매 프레임 캐릭터의 기본 애니메이션 상태를 갱신하고 있어, 스킬 시스템이 재생한 애니메이션과 Animator 제어권이 충돌하고 있었습니다.

즉, 이동 상태와 스킬 상태가 서로 독립적으로 Animator를 변경하는 구조가 원인이었습니다.

해결

스킬 사용 여부를 별도의 상태로 관리하고, 스킬 실행 중에는 이동 컨트롤러의 기본 애니메이션 갱신을 제한했습니다.

또한 일부 스킬은 PlayableGraph를 이용해 AnimationClip을 직접 재생하도록 구성하여, 기존 Animator Controller를 크게 변경하지 않고 스킬 애니메이션을 안정적으로 제어했습니다.

결과

Idle/Run상태가 스킬 애니메이션을 중간에 덮어쓰는 현상을 해결했습니다.

DownStrike와 ShieldBlock의 애니메이션이 끝까지 안정적으로 재생되고, 스킬 종료 후 자연스럽게 기본 이동 상태로 복귀하도록 개선했습니다.

키 바인딩 데이터 수명 주기

문제

GameEntry에서 설정한 키 바인딩이 보스전까지는 유지되어야 했지만, 이전 Play나 Restart 이후의 설정까지 다음 게임에 남는 문제가 발생했습니다.

이 때문에 새로 게임을 시작했는데도 이전 스킬 배치가 남아 있거나, Ready 상태와 실제 키 설정이 서로 맞지 않는 상황이 생겼습니다.

원인

키 바인딩 데이터를 PlayerPrefs에 저장하면서, 전투 준비 과정에서만 필요한 데이터를 영구 저장 데이터처럼 관리하고 있었습니다.

하지만 이 프로젝트의 키 설정은 사용자 옵션이 아니라 GameEntry → Ready → Boss Battle 동안만 유지되면 되는 세션 데이터였습니다.

해결

영구 저장 방식인 PlayerPrefs를 제거하고, 현재 Play 세션 동안만 유지되는 static Dictionary를 사용하도록 구조를 변경했습니다.

또한 Archer와 Warrior의 바인딩 데이터를 분리하고, 새 Play 시작이나 Restart, GameEntry 재진입 시점에는 세션 데이터를 명시적으로 초기화하도록 처리했습니다.

결과

키 설정은 씬 전환 후 보스전까지 정상적으로 유지되면서도, 새로운 게임을 시작할 때는 이전 설정이 남지 않도록 개선했습니다.
